# 수리 질문 게시판

## 구성과 운영

- questions.html: 최신 질문·분야·부산 구군·답변 대기·검색·페이지 이동.
- question-write.html: 비회원 질문·최대 3장 사진·6자 이상 글 비밀번호.
- question.html?id=...: 공개 답변·신고·비밀번호 확인 후 수정·삭제.
- question-admin.html: 인증된 답변 담당자 전용 관리. 공개 메뉴에 연결하지 않고 noindex 적용.
- board-notice.html: 공개·보관·운영 문의 안내.
- questions-example.html: 운영 확인용 별도 예시. 실제 질문 데이터와 분리.

기존 사이트를 React/Next.js로 전환하지 않았다. 작업 데이터는 기존 카탈로그를 참조한다.
`node tools/build-board-pages.cjs`는 공통 헤더·푸터와 서버의 작업 ID/분야 매핑을 생성한다.

관리자는 질문을 펼쳐 답변·관련 작업·공개 여부를 정하고 미리보기 후 저장한다.
비공개 답변은 고객에게 보이지 않는다. 경력 표시는 컴퓨터 질문에만 노출한다.
관리 목록은 최근 200개를 불러와 필터한다. 초기 규모를 넘으면 서버 페이지 이동을 추가해야 한다.
자동 알림·일반 댓글·채팅·좋아요·예약·결제는 구현하지 않았다.

## 권한

비회원 글 비밀번호는 서버에서 PBKDF2-SHA256 600,000회와 무작위 salt로 해시한다.
원문 비밀번호를 응답·주소·브라우저 저장소에 넣지 않는다. 확인된 글 관리 권한은 해당 글에만
15분간 적용하고 메모리에서 유지한다. 관리자 세션도 메모리에만 유지해 새로고침 시 재로그인한다.

모든 게시판 테이블에 RLS를 켜고 anon/authenticated 직접 접근을 차단한다.
관리자 API는 사용자 토큰을 Supabase에서 검증한 후 활성 관리자 등록 여부를 확인한다.
일반 Supabase Auth 사용자로 로그인하더라도 관리자 권한은 없다.

사진은 실제 형식·크기·차원을 검사하고 서버에서 JPEG로 재인코딩해 비공개 저장한다.
공개 사진 요청마다 질문 상태를 확인하며 숨김·삭제 시 사진 접근도 차단한다.
작성·조회·신고·비밀번호 확인 요청에 속도 제한을 적용한다.

## 보관·백업

삭제 글·답변·사진은 공개 접근을 차단하고 30일 후 정기 정리한다.
매일 한국시간 04:15에 정리 작업 실행. 처리 완료 신고와 관리자 기록은 90일 후 정리한다.
만료 관리 권한, 원본 IP 대신 HMAC 처리한 공격 방지 식별값, 연결 없는 업로드도 정리한다.
정리 호출용 난수는 Supabase Vault에만 보관하며 방문자 호출을 차단한다.

원본 파일 백업: F:/yessuri-web/review-backups/board-20261019-2026-10-19T06-38-37-011Z/.
데이터 백업은 저장소 밖 `review/backup-board-data.cjs`로 수동 실행한다.
질문·답변·관리자 매핑·비밀번호 해시·사진을 AES-256-GCM으로 암호화하고 키를 Windows DPAPI로 보호한다.
관리자는 별도 백업 사본을 30일 안에 정리해야 한다. 자동 데이터 백업은 설정하지 않았다.

복원 순서: 동일 스키마 → Supabase Auth 사용자 확인 → 관리자 매핑 → 질문·비밀번호 해시 →
답변·사진 메타데이터·신고 → 같은 경로의 비공개 사진 파일. 공개·숨김 상태와 권한을 다시 검증한다.
로컬 암호화 백업은 해당 Windows 사용자의 복호화 권한이 필요하다.

## 배포와 되돌리기

프런트는 기존 GitHub Pages, 서버는 예스수리 전용 Supabase(서울)를 사용한다. Yesmoa는 변경하지 않는다.
서버 키·승인 토큰·백업 파일은 Git에 넣지 않는다. 이번 게시판 커밋을 되돌려 사이트를 복원할 수 있다.
운영 질문이 쌓였다면 먼저 백업하며 테이블·저장소를 무작정 삭제하지 않는다.
별도 예시 화면은 questions-example.html·board-examples.js만 제거하면 되며 실제 고객 데이터에 영향이 없다.
