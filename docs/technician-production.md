# 기술자 비공개 접수 운영

- 공개 목록: `/technician-board.html`, 신청: `/technician-apply.html`, 본인 조회: `/technician-lookup.html`, 관리자: `/technician-admin.html`.
- 운영 관리자 인증은 기존 Supabase 이메일 계정과 비밀번호를 사용한다. 활성 관리자 허용 목록은 `technician_private.admins`이며 초기 전환 시 기존 활성 게시판 관리자를 복사했다. 로컬 `admin` 계정은 운영에서 사용할 수 없다.
- `technician_private` 테이블은 RLS와 권한 회수로 공개 접근을 차단한다. `technician_rpc`는 service_role만 실행한다. Edge 함수가 인증과 입력을 검사하고 RPC가 세션과 대상 권한을 다시 검사한다.
- 신청 비밀번호는 PBKDF2-SHA256 600,000회, 무작위 salt로 저장한다. 원문을 보관하지 않는다. 조회 토큰은 서버에 SHA256 해시로 보관하며 본인15분·관리자30분 만료다. 브라우저 sessionStorage에는 만료되는 조회 토큰만 저장한다. 비밀번호를 저장하거나 URL에 넣지 않는다.
- 사진은 비공개 `technician-private` 버킷에 저장한다. 인증된 API가 직접 전송하고 화면은 blob URL을 사용한다. 영구 공개 URL이나 URL 토큰은 없다. 원본 입력은5장·각10MB까지, 브라우저에서1280px/JPEG/1MB 이하로 변환하고 서버가 형식·크기를 재검증하고 재인코딩한다. 원본은 저장하지 않는다.
- 개인정보 보관은 신청일+6개월. 매시25분 `yessuri-technician-retention` 작업이 만료 데이터·사진과 실패 업로드·삭제 사진을 정리한다. 비밀 키는 Vault에만 보관한다. 최소 처리 이력은90일 뒤 정리한다.
- 프로필 공개는 별도 협의 절차다. 구글 폼과 응답은 변경·이전하지 않았다. 등록 안내의 접수 링크만 새 게시판으로 전환했다. 자동 문자·이메일 알림은 없다.
- 관리자는 신청 상세의 ‘공개 프로필 등록’에서 공개 업체명·분야·지역·소개·경력을 검토하고 신청자의 공개 동의를 확인한 뒤 등록한다. 연락처는 별도 공개 동의를 체크한 경우에만 저장한다. 비공개 첨부사진·담당자·접수번호·메모·답변은 자동 복사하지 않는다. `GET/POST /api/admin/applications/:id/public-profile`은 기존 관리자 세션을 확인하며, POST는 신청 버전을 확인하고 고정 ID `technician-신청UUID`로 한 번만 삽입한다. 이미 등록된 프로필은 덮어쓰지 않고 확인 링크를 제공한다. 이 기능 배포에는 `technician-api` Edge 함수와 상세 화면 파일을 함께 반영해야 하며 기존 `expert_profiles` 테이블을 사용하므로 신규 DB 마이그레이션은 없다.
- UI 테스트는 별도 테스트 스키마와 버킷을 사용하며 운영에 가짜 신청을 넣지 않는다.
- 되돌리기: 배포 커밋을 revert하여 등록 안내 링크를 복원한다. 운영 신청이 생겼다면 스키마·버킷을 삭제하지 말고 백업 및 보관 정책에 따라 별도 전환한다.
